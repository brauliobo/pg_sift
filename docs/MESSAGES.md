# Messages: every NOTICE, WARNING and INFO of pg_sift

Generated by `scripts/gen-messages.sh` from `docs/messages.tsv`; do not edit by hand. `scripts/gen-messages.sh --check` (lint) fails when a message of `src/` or `sql/` has no row, when a row names a message that no longer exists, when the DETAIL or HINT of a row differs from the source, and when a number of a row is in none of the measurements it cites.

pg_sift tells what it chose on its own and what it advises, in the message levels the client shows by default: **45 NOTICE**, **8 WARNING** and **8 INFO** (the lines `VACUUM VERBOSE` adds). Every message has one row below: the exact text (`%s`, `%d`, `%u`, `%.0f` are the values it fills in), where and when it appears, the decision pg_sift took, the benefit and the trade-off of that decision with a measured number, and how to change it or switch it off. A cell that says *no measured number yet* is a measurement nobody made yet.

- `SET client_min_messages = warning` hides the NOTICEs and the INFO lines for the session; the choice they report is made either way. `ALTER DATABASE .. SET client_min_messages = warning` or `ALTER ROLE` keeps it.
- The DETAIL and HINT of a message are listed in full [at the end](#detail-and-hint-in-full). An ERROR with its HINT is not in this table: the refusals of the aggregate scan are in [USAGE](USAGE.md#why-a-query-kept-the-normal-plan) and the limits in [LIMITS](LIMITS.md). LOG and DEBUG messages go to the server log, not to the client, and are not listed.
- Numbers are in the units of their source: instructions of one backend, milliseconds, bytes, percent of the index; the conditions (rows, columns, version) are in the cited option case of [OPTIONS](OPTIONS.md).

## DETAIL and HINT in full

The text after the message line, as `psql` prints it (`%s`, `%d` fill in values). A DETAIL or HINT built from pieces at run time shows its fixed sentences.

- **array-lengths** (NOTICE)
  - DETAIL: cardinality(x), array_length(x, 1) and x IS [NOT] NULL are read from two integer columns of each array, without the array: about a byte a row for each.
  - HINT: ALTER INDEX %s SET (array_lengths = 'off'), then REINDEX, drops them.
- **jsonb-paths** (NOTICE)
  - DETAIL: They are the keys that are a scalar of one type in most of a sample of %d documents, a map of more than 4 keys of one type as a wildcard, an array of objects as a group; a REINDEX keeps them, and ALTER INDEX ... SET (paths = 'auto') then REINDEX reads the documents again.
  - HINT: Write paths = '...' to fix them by hand.
- **key-lists** (NOTICE)
  - HINT: ALTER INDEX %s SET (key_columns = 'off'), then REINDEX, turns it off; key_columns = 'a, b' on CREATE INDEX names the columns.
- **array-elements** (NOTICE)
  - HINT: ALTER INDEX %s SET (paths = ''), then REINDEX, leaves the elements out.
- **cube-ranking** (NOTICE)
  - DETAIL: The cube holds at most %d dimensions, the calendar cells of the dates among them. A column with more than %d distinct values in a unit has no histogram there, so a dimension given to it holds nothing. Stretches of about a unit (%d of them, spread over the table) were read, and the columns that fit most of them come first.
  - HINT: ALTER INDEX %s SET (preagg = 'default'), then REINDEX, gives them in the order of the columns; preagg = 'cube(...)' names them.
- **rows-rollup** (NOTICE)
  - DETAIL: A GROUP BY or a filter of both columns is read from the cells of each unit. Their combinations fit the cells a unit may keep (a tenth of its rows, at most %d) in at least %d% of %d sampled stretches of about a unit, about %d of them a unit; the cells add to the index and to its build.
  - HINT: ALTER INDEX %s SET (rollup_dims = 'off'), then REINDEX, drops it; rollup_dims = 'a, b: measure' names the columns.
- **text-compression** (NOTICE)
  - HINT: ALTER INDEX %s SET (compression = 'auto; %s=zstd') and REINDEX keeps zstd for a column, 'auto; %s=lz4' takes lz4.%s
- **key-cut-chosen** (NOTICE)
  - DETAIL: A sample of %.0f superblocks shows the values of "%s" spread over the units, and no other leaf of the index follows the order of the table%s. The units are cut by the leaf, so %s reads the few units of its range; the addresses of the rows of a unit are in the index.%s%s
  - HINT: ALTER INDEX %s SET (key_cut = 'off') and REINDEX keep the units by block range.
- **key-cut-advised** (NOTICE)
  - DETAIL: The predicted size comes from a sample of %.0f superblocks; an automatic cut is chosen only when its benefit is at least its cost (here %.0f against %.0f: a gain of 5% in a lookup is one unit of benefit, 3% of growth and 5% of build instructions one of cost). No other leaf follows the order of the table.
  - HINT: CREATE INDEX .. WITH (key_cut = '%s'), or ALTER INDEX %s SET (key_cut = '%s') and REINDEX, if the lookups of this key matter more than the size.
- **key-cut-clustering-advice** (NOTICE)
  - DETAIL: key_cut = '%s' cuts the units by that key instead of by block range, so a lookup reads the few units of its range and keeps doing so through writes and merges without a rewrite of the table; no leaf loses its zones, and the index grows by the address lists of the units.
  - HINT: CREATE INDEX .. WITH (key_cut = '%s'), or ALTER INDEX %s SET (key_cut = '%s') and REINDEX; sift.cluster_advice() says the same for an index built before, and the setting sift.cluster_advice = off silences both.
- **point-directory-auto** (NOTICE)
  - HINT: ALTER INDEX %s SET (point_tid_columns = 'off') and REINDEX keep the index without it.
- **point-tid-explicit** (NOTICE)
  - DETAIL: A lookup of the access method returns the addresses without reading a unit, except for a unit with a dead row; the segments are of a column format that a library before 3.7 cannot read, and the build sorts the keys of the column.
  - HINT: Drop the option, or set sift.col_format_minor to 14, to list the rows of the segment instead.
- **point-tid-key-cut** (NOTICE)
  - DETAIL: The units of a key-cut segment are not block ranges, so a heap address does not name its unit: a lookup reads the unit of each row, as with point_columns.
- **order-array-ends** (NOTICE)
  - DETAIL: The first and last %u entries of each segment and its first NULL rows, under 0.1 bytes a row of those columns; the segments are column format minor %d, which a library before %s cannot read. The build chose the columns from the statistics of the table: 100,000 rows or more, 1,000 or more distinct values and a correlation with the heap order under 0.99 (the zones cannot skip units), at most %d of them (a table with no statistics is analyzed first). A column keeps the whole order when a scan with a bound in the middle of its values would read more cold blocks than the order's bytes are worth (%d kB of index a block), else the ends: %s.
  - HINT: ORDER BY column [DESC] LIMIT n, and the same with a bound at the end of the order (column >= x ORDER BY column DESC LIMIT n), read n entries of an end, whatever the number of units, for n and an OFFSET up to the entries of the end; a range in the middle of the column reads the units. ALTER INDEX .. SET (order_array_columns = 'off'), then REINDEX, drops them; order_array_columns = 'column' keeps the whole order of a column.
- **order-array-group** (NOTICE)
  - DETAIL: %.1f bytes a row for each array, %.1f MB together; the segments are column format minor %d, which a library before %s cannot read. The build chose them from the statistics of the table: 100,000 rows or more, 1,000 or more distinct values, a correlation with the heap order under 0.99 (the zones cannot skip units) (a table with no statistics is analyzed first); the group is the integer column of most values that has 100 or more and at least 3 rows apiece.%s%s
  - HINT: A range of the column (up to 16,384 rows) hands the heap the addresses between its bounds without reading a unit, ORDER BY column LIMIT n reads n entries, whatever the number of units, and WHERE %s = x ORDER BY column LIMIT n reads n entries of x. ALTER INDEX .. SET (order_array_group = 'off'), then REINDEX, drops the second order; (order_array_columns = 'off') drops both.
- **order-array-auto** (NOTICE)
  - DETAIL: %.1f bytes a row for each column, %.1f MB together; the segments are column format minor %d, which a library before %s cannot read. The build chose them from the statistics of the table: 100,000 rows or more, 1,000 or more distinct values, a correlation with the heap order under 0.99 (the zones cannot skip units), at most %d of them, and for a text column that the default formula pays (a table with no statistics is analyzed first). A column keeps the whole order when a scan with a bound in the middle of its values would read more cold blocks than the order's bytes are worth (%d kB of index a block).%s%s
  - HINT: A range of the column (up to 16,384 rows) hands the heap the addresses between its bounds without reading a unit, and ORDER BY column LIMIT n reads n entries, whatever the number of units. ALTER INDEX .. SET (order_array_columns = 'off'), then REINDEX, drops it; set sift.col_format_minor to 14 to write none.
- **order-array-listed** (NOTICE)
  - DETAIL: %.1f bytes a row for each column, %.1f MB together; the segments are column format minor %d, which a library before %s cannot read.
  - HINT: ORDER BY column LIMIT n reads n entries of the array and n rows of the heap, whatever the number of units, and a range of the column (up to 16,384 rows) hands the heap the addresses between its bounds without reading a unit. Drop the option, or set sift.col_format_minor to 14, to keep the sorted runs only.
- **order-array-text** (NOTICE)
  - DETAIL: ORDER BY %s LIMIT n reads n entries of each segment, where the units compare the strings of every row (100,000 rows: 82.8 M to 0.27 M instructions). The array takes about %.0f bytes a row (%.0f% of the index, G) and CREATE INDEX does about %.0f% more instructions (W)%s: the benefit is log2(%.0f) / log2(1.05), the cost G / 3 + W / 5.
  - HINT: ALTER INDEX %s SET (order_array_columns = 'off'), then REINDEX, drops it; order_array_columns = '%s' keeps it by name.
- **order-array-text-declined** (NOTICE)
  - DETAIL: ORDER BY %s LIMIT n would read n entries of each segment, where the units compare the strings of every row. The array takes about %.0f bytes a row (%.0f% of the index, G) and CREATE INDEX would do about %.0f% more instructions (W)%s: the cost is G / 3 + W / 5 against the benefit log2(%.0f) / log2(1.05).
  - HINT: CREATE INDEX .. WITH (order_array_columns = '%s'), or ALTER INDEX %s SET (order_array_columns = '%s') and REINDEX, if ORDER BY %s LIMIT n matters more than the build.
- **order-array-few-values** (NOTICE)
  - DETAIL: ORDER BY %s, key LIMIT n OFFSET m reads the rows of the group of equal values the offset ends in, where the units read every row (300,000 rows of 365 values, OFFSET 10,000: 113 M to 11 M instructions). The array takes about %.0f bytes a row (%.0f% of the index) and CREATE INDEX about %.0f% longer.
  - HINT: ALTER INDEX %s SET (order_array_columns = 'off'), then REINDEX, drops it; order_array_columns = '%s' keeps it by name.
- **order-layout** (NOTICE)
  - DETAIL: A compact chunk of an order array keeps the heap address of each row and its key rounded to a bucket of a few bits; the heap settles ties and gives the exact key of the rows a scan needs. The build keeps a chunk compact where that is at least a fifth smaller than keeping the exact keys and it has no run of %d equal keys or more. The segments with a compact chunk are column format minor %d, which a library before %s cannot read.%s%s
  - HINT: ALTER INDEX .. SET (order_layout = 'whole') and REINDEX, or a merge, write exact keys only; 'compact: column' and 'whole: column' choose it for a column.
- **primary-key-not-indexed** (NOTICE)
  - DETAIL: %d table%s ("%s"%s) reference it with a foreign key. The aggregate scan of two sift tables joined on a key that is not a column of both indexes keeps the normal plan (join_condition), and the column adds a few bytes a row.
  - HINT: Add the column to the index if queries join on it.
- **foreign-key-not-indexed** (NOTICE)
  - DETAIL: A join to "%s" on them keeps the normal plan (join_condition) and the scan cannot filter the table by the keys of another table's rows; a column adds a few bytes a row.
  - HINT: Add the columns to the index if queries join on them.
- **hot-update-columns** (NOTICE)
  - DETAIL: Each such update writes a new row version into every index of the table (measured on a 13-column index: 0% HOT updates against 28%, 23.7k against 38.7k updates a second, 2,175 against 1,493 bytes of WAL an update), and the index keeps the old one until a merge or a REINDEX.
  - HINT: Leave the column out of the index if it is rewritten far more often than it is aggregated; keep it if its aggregates are the reason for the index.
- **key-order** (NOTICE)
  - DETAIL: The options you wrote stay. The units are cut by the key and the rows of each kept in its order, which pays when the table is stored in that order: ORDER BY .. LIMIT, OFFSET, ranges and lists of values read entries and units, not rows at random. On a table in arrival order an ordered LIMIT costs what it does without the option, and the index grows and merges as with key_cut.
  - HINT: ALTER INDEX %s RESET (key_order), then REINDEX, builds the index without it.
- **wildcard-keys-overflow** (NOTICE)
  - DETAIL: The keys and values past the limit are read from the heap, and a query that reads the leaf keeps the normal plan.
  - HINT: Declare the keys that queries read by name in the paths option instead of a wildcard, or keep the map out of the index.
- **string-overflow** (NOTICE)
  - HINT: Index an expression that keeps the part of the value that is used, such as left(column, 255).
- **cube-dim-no-histogram** (NOTICE)
  - DETAIL: A query that groups or filters by it scans those units (sift.col_rollup_misses counts them).
  - HINT: Group by a leaf with fewer values per unit, or sort the table by it before REINDEX.
- **keys-bloom-filter** (NOTICE)
  - DETAIL: The filter skips the units that lack the key of an equality or IN test; a count(DISTINCT) of the column scans them. A unit holds up to %u distinct keys.
- **keys-no-summary** (NOTICE)
  - DETAIL: A summary that could not skip a unit is not stored; a query that filters by the column scans those units.
  - HINT: Leave "%s" out of key_columns, or sort the table by it before REINDEX.
- **keys-no-list** (NOTICE)
  - DETAIL: A count(DISTINCT) of the column scans those units; their keys are a bloom filter where there are more than %d, else exact or, where they fill their range, nothing.
  - HINT: Leave "%s" out of key_columns, or sort the table by it before REINDEX.
- **rollup-not-written** (NOTICE)
  - DETAIL: A unit keeps at most a tenth of its rows as cells, and at most %d; a query that groups by those columns scans the others.
  - HINT: Name fewer columns, or columns with fewer values per unit.
- **cube-columns-left-out** (NOTICE)
  - DETAIL: The calendar cells of the date and timestamp columns come first and then %s; a query that groups or filters by those columns scans the units.
  - HINT: Give preagg = 'cube(...)' the dimensions the queries group by (sift.index_advice lists the columns that qualify), or preagg = 'auto' to give them to the columns whose histograms fit.
- **calendar-columns-left-out** (NOTICE)
  - DETAIL: The cube holds at most %d dimensions, and the other columns of the index take the rest; a query that groups by those dates scans the units.
  - HINT: Name the columns the queries group by in calendar_columns (the list must fit the %d dimensions), or give preagg = 'cube(...)' only the dims they need.
- **auto-merge-on** (NOTICE)
  - DETAIL: A background worker vacuums "%s" when a thousandth of its rows changed and rewrites the index after the VACUUM, within sift.col_auto_merge_wal_pct of the WAL the server writes.
  - HINT: SET sift.col_auto_merge = off for the server or the database to stop it; sift.col_maintenance_status(index) shows where it stands.
- **auto-merge-autovacuum-off** (NOTICE)
  - DETAIL: The units answer from their pre-aggregates again only after a VACUUM of the table, and the merge of the index follows that VACUUM.
  - HINT: Run VACUUM on it from a job, or RESET autovacuum_enabled.
- **rewrite-chose-again** (NOTICE)

  - HINT: ALTER INDEX %s SET (key_cut = 'off') (and the same for the others) keeps a choice off.
- **maintenance-failed-text-index** (WARNING)
  - DETAIL: It is retried later, after a growing delay.
- **maintenance-failed-column-index** (WARNING)
  - DETAIL: It is retried later, after a growing delay.
- **write-buffer-stays-open** (NOTICE)
  - DETAIL: The last maintenance step failed: %s
  - HINT: Run sift.merge() on the index; sift.workers shows what the background did.
- **analyzer-options-changed** (WARNING)
  - DETAIL: Queries and inserts on its table fail until the index is rebuilt with REINDEX.
  - HINT: To change them without downtime, CREATE INDEX CONCURRENTLY a new index with the options and drop this one.
- **siftagg-not-used** (NOTICE)
  - DETAIL: arm: %s
