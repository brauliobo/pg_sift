# Format numbers

Next free column format minor: 56

Every number written to disk or checked on upgrade, and who claims it. A new feature takes the next free number here before one in the code; two released features never share a number or a flag. The features of one release that no earlier release shipped share that release's minor (4.3: 44), since a library before it refuses all of them the same way.

## 2. Metapage (`SiftMetaPageData`, `src/core/sift.h`)

Format major 1. The minor is what a build must read to understand an index or table; a build refuses a larger one with a REINDEX hint (`check_meta`). A metapage starts at `SIFT_FORMAT_MINOR_BASE` (2); only the first segment that needs more raises it and nothing lowers it, so an index without newer structures stays readable by 3.0.

| minor | meaning | raised by |
|---|---|---|
| 1.1 | term blobs may end with a position stream | BM25 index with positions |
| 1.2 | segment format 2 | BM25 index |
| 1.3 | BM25: segments of segment format 3. `sift_table`: a column group with unfrozen rows (`SIFT_SEG_VERS`) | the first such segment |
| 1.4 | BM25: segments of segment format 4 (the position stream in blocks). A `sift_table` stays at 1.3 | the first such segment |
| 1.5 | BM25: segments of segment format 5 (the values of the INCLUDE columns). A `sift_table` stays at 1.3 | the first such segment, of an index that names INCLUDE columns |
| 1.6 | BM25: a write buffer of buffer format 6 (`SIFT_WBUF_FORMAT_WIDE`, below). A `sift_table` stays at 1.3 | the first such buffer: the next insert into a BM25 index after the upgrade opens one |
| 1.7 | A chained directory (`SIFT_DIR_CHAINED`, `SIFT_PT_DIRROOT`, `SIFT_PT_DIRLEAF`, `src/core/page.h`), in an index of any access method: block 1 keeps the version and the lock of the directory and holds no entry, the entries are in leaf pages that a root page lists (64-byte references: page, entries below, where they start in the leaf, version, partition lineage, an exact 40-byte lower bound; a leaf holds the entries of several partitions, a reference each; at most 127 references a page, and past that the root lists interior pages of references, 3 pages deep at most), and block 1 names the root (the struct of the metapage is the one of 5.0). An update writes the leaves it changes and a new root, each page once and logged before anything refers to it, then flips the root and the version in block 1 in one generic WAL record; the replaced pages go through the free list with the horizon of a released extent. A library that reads 1.6 refuses the index. The same minor marks a `sift_col` index whose write buffer is of column format 55 (key ranges in the page heads, below): 5.0 does not look at the format of a buffer entry and would read the longer page head as damage, so the metapage says what it cannot read | the first directory update that does not fit block 1 (an index of more than 128 entries); the first write buffer of column format 55 (the next write into such an index opens one). A chained directory never returns to block 1, however few entries it comes to: there is no path back, and a chain of one root and one leaf, which is what up to 127 partitions make, costs a read of two pages more than block 1 |

`sift_col` indexes are never raised: their segment formats are the column engine's (section 4).

Metapage flags: `SIFT_COL_META_FLAG` 0x00010000 (a `sift_col` index), `SIFT_TBL_META_FLAG` 0x00020000 (a `sift_table`); the low byte is the
failure count (`SIFT_META_FAILURES_MASK`).

The fields past the base of the metapage (`SiftMetaPageData`: the failure note, the analyzer configuration, the floor of the stamps of a scope index `scope_floor`, what the reads paid for the changed pairs of its scopes `scope_paid`, and what they paid for the open write buffer and the tombstone log `reads`: two pairs of generation and sum, `col/wbuf/reads.c`, and what the workers did last: the end, the job and the time of the last background step that ended well, the failures counted for good and the last shrink of the file with why the next is blocked, `maint_ok_at`, `maint_ok_job`, `maint_ok_ms`, `failures_total`, `last_shrink` and `shrink_blocked`) are not a format minor: `pd_lower` covers them once one is set, a metapage that ends short of them reads as zeros, and only a record of the metapage alone (`sift_meta_update`, which leaves the directory and its version alone) or the switch that owns a field writes them. `check_meta` refuses a metapage whose `pd_lower` is past the struct of the build, as a bad metapage: **a build older than the fields reads an index that a newer build wrote them in as corrupt** (the minor, which would say what to install, is read after it; the hint of `check_meta` and the upgrade order of docs/UPGRADING.md, standbys first, are the rule). `reads` is written for any `sift_col` or BM25 index whose write buffer or tombstone log was read by a statement, `scope_paid` for an index with a scope, so since 5.0 a 4.3 library refuses an index that was read once by a 5.0 server; nothing lowers `pd_lower`. A sum is for the generation of the segment it was paid for, which is never reused: a note for a newer generation starts it again, one for an older is dropped, so nothing zeroes it when the buffer is promoted or the log rewritten.

## 3. BM25 segments (`SiftSegEntry.format`, access method `sift`)

The write buffer of a BM25 index is a lane chain whose directory entry has a format of its own (not a segment format): 0, pages with the 256-bit bloom of term hashes in the header (`SiftWbufPageHeaderData`), which a page of 900 terms and more fills, so that a term in no document of the buffer still reads every page; 6 (`SIFT_WBUF_FORMAT_WIDE`, 4.2), the same header followed by a bloom of 8,192 bits (`SiftWbufWideHeaderData`, 2 probes: bits 0..12 and 13..25 of the term hash; 4% false positives at 900 terms). A buffer keeps the format it was opened with, and a library of 4.2 reads both, so an upgrade has no manual step: the buffer open at the upgrade is read as it is and the one opened after it is format 6. The first buffer of format 6 raises the metapage to 1.6, which a library of 4.1 or older refuses (`check_meta`: it reads formats 1.0 to 1.5, REINDEX or install the release that wrote the index); nothing lowers it.

| format | name | written by |
|---|---|---|
| 1 | `SIFT_SEGFMT_RANKBITS`: one liveness bit per doc in rank order | SQLite and MariaDB hosts |
| 2 | `SIFT_SEGFMT_LIVEROWS`: liveness rows per superblock, dead-posting table | 3.0 |
| 3 | `SIFT_SEGFMT_PACKED`: dictionary blocks, narrower docmap rows, packed containers (perf/BM25-SIZE.md section 5) | 3.1 PostgreSQL |
| 4 | `SIFT_SEGFMT_POSBLK`: the position stream of a term in blocks of 32 postings, bit-packed (`bm25/posblk.c`, perf/BM25-SIZE.md section 5.4); a dictionary block says so with `SIFT_DICT_POS2` | 3.7 PostgreSQL |
| 5 | `SIFT_SEGFMT_ATTR`: format 4 with the values of the INCLUDE columns: per column and SB one record (a 24-byte `SiftAttrColHdr` of the smallest value, the code of an unknown value, the width and the flags (1: no rows; 2: no document of the SB is unknown, so the smallest value and the code give its exact range and a test that no value of it passes drops the SB), then the row of each present page, `width` bits a slot: 0 is NULL, `v - base + 1` a value, the unknown code a document whose heap tuple was gone) after the docmap records, and a docmap trailer `SiftAttrRef[nsb][ncols]`, `u64 recs_end`, `u32 ncols`, `u32 nsb` (`bm25/segment.h`, `bm25/segment_int.h`) | 4.0 PostgreSQL |

A 4.0 build reads 1 to 5 side by side, and writes format 5 only for an index with INCLUDE columns (the others stay at 4: a 3.7 library still reads them); a merge writes the current format. 3.0 refuses a segment of format 3, 3.6 and older one of format 4, and 3.7 and older one of format 5, through the metapage minor
(section 2); `REINDEX` with the older library rewrites it.

## 5. Segment entry flags (`SiftSegEntry.flags`)

| flag | value | meaning |
|---|---|---|
| `SIFT_SEG_DIRTY` | 0x0001 | some liveness bit cleared |
| `SIFT_SEG_POSITIONS` | 0x0002 | written with word positions |
| `SIFT_TBL_SEG_WBUF` | 0x0100 | `sift_table` write buffer |
| `SIFT_TBL_SEG_TOMB` | 0x0200 | `sift_table` tombstone segment |
| `SIFT_SEG_ROOTS` | 0x0004 | column segment whose documents were shredded with a string root stored as the overflow of every column below it (below) |
| `SIFT_SEG_XSTAMP` | 0x4000 | column segment of a heap index with `track_changes` whose inserters all committed before the xid in `reserved` ([COL-HEAPFREE.md](COL-HEAPFREE.md)) |
| `SIFT_SEG_XPENDING` | 0x0040 | the same while some inserters had not finished: `reserved` is the xid, `pad` the latest of those that had not, `sum_dl` a bit for each; reads take it for a segment without a stamp, maintenance settles it |
| `SIFT_SEG_VERS` | 0x0400 | column segment with unfrozen rows (`reserved` is the smallest xid); cleared when the rows are frozen |
| `SIFT_SEG_NET` | 0x2000 | column segment with the pre-aggregates of its dirty units net of their dead rows, in whole pages at the end of the stream (below) |
| `SIFT_SEG_BYTID` | 0x0010 | keyed column segment cut by TID range (the units of `sift.col_unit_floor`): its units follow each other in the order of the TIDs; no column format minor (a reader that does not know the flag reads it as keyed) |
| `SIFT_SEG_BYKEY` | 0x0020 | keyed column segment cut by the range of a key: its units follow each other in the order of that key; no column format minor |
| `SIFT_SEG_CUTREC` | 0x0080 | with `SIFT_SEG_BYKEY` (5.0): the segment records the leaves it is cut by (below); no column format minor |

- `SiftSegEntry.sum_dl` of a `sift_col` write buffer is the mask of leaves holding a JSON null; 3.2 only.
- `SiftSegEntry.reserved` is the owner's tag for an immutable `sift_col` segment and the smallest xid when `SIFT_SEG_VERS` is set.
- `SIFT_SEG_ROOTS` (4.2) needs no column format minor either (a segment entry flag, as `SIFT_SEG_NET` and `SIFT_SEG_LSTATS`). The segment's documents were shredded with a document that is a JSON string stored as the overflow of every column
  declared below it (shape, JSON type none), as a document that is an array always was; before, such a document left every column absent, which is what a missing key leaves, so no read could tell `'"k"'::jsonb ? 'k'` from `'{}'::jsonb ? 'k'`.
  The bytes are the same, so a build that does not know the flag reads the segment as before (a string document is a missing key, the overflow stays a value its reads give as NULL), and a merge or rewrite by it drops the flag. A merge keeps the flag
  only when every segment it reads has it; a write buffer (lane) carries it from the first row. The segments written before have no flag: a read that needs it (`doc ? 'k'`) reads all their NULL slots from the heap, and VACUUM sets the flag
  on every unflagged segment when it finds no version of any row, dead or alive, whose document in a `jsonb` column of the index is a string (`src/col/maint/roots.c`; the entries are the only thing it writes).
- `SIFT_SEG_NET` (4.0) needs no column format minor, as the leaf statistics (`SIFT_SEG_LSTATS`) needed none: a build that does not know the flag lists the pages in the header's extents like any others and never looks in them, so it reads the
  segment as written and a rewrite or merge by it drops the sidecar with the segment. The sidecar starts at a page boundary after the segment's own stream (and its leaf statistics); the last 16 bytes of the stream are
  `{magic 0x5445474e, offset of the sidecar}`. The sidecar is `NetHeader`, `NetUnit[nsb]` (the dead rows the unit had when it was made, the lengths of its cube and rollup blobs), `NetAgg[ncols][nsb]` (the zone and exact
  sums of each leaf over the live rows) and the blobs, the bytes `sift_cpagg_cube` writes for the live rows with the dims, rollups and measures of the unit's own blobs (`src/col/seg/net.c`). VACUUM writes it
  (`src/col/maint/net.c`): the segment keeps its generation and its header page is written again, as a relocation does, with the extents of the stream and those of the new sidecar; the old header page and the old sidecar
  are released together with the directory switch. A reader uses the unit's net blobs when the unit has exactly the number of dead rows they were made for (liveness bits are only cleared), else it reads the unit as before.
- `SIFT_SEG_CUTREC` (5.0) needs no column format minor either. A segment cut by the range of a key (`key_cut`, a scope) records the leaves it is cut by, most significant first (`SIFT_COL_CUT_MAX`, 4, at most), in the schema section of its header: after the bytes of the schema and before the stamps of the connections and scopes, `int16` leaf numbers, then a `uint32` number of leaves and the magic `CCUT` (0x54554343); `dictroot_off` counts it. A reader that does not know the flag parses the schema from its start and the stamps from the end of the section, so it never meets the record. A merge streams an input only if its record is the cut the merge reads (the order of the leaves of the `key_cut` of the index, or of the TIDs when the index has none, where a segment cut by TID range or by superblock is); the rows of any other input are sorted again, loaded whole when they fit `maintenance_work_mem` and else by a sort that spills to temporary files (`col/order_sort.c`: the key leaves and the TID as sort keys, the row packed as `col/rowpack.c` writes it). A keyed segment without the flag (written by any release before 5.0, or by a 5.0 build before the record) has its units checked once by the first merge that meets it (`sift_colk_streams`) and is streamed when they are in the order the merge reads, whatever the option was when it was written. A merge by a build that does not know the flag writes its output without it.
- The mirror (4.3) needs no column format minor and no flag: the header page of a segment holds, after its extents, a copy of the small ranges of the stream that a plan and the first read of the segment open (the schema, the unit
  directory, the point directories, the first bytes of each order block, the zone directory, the headers of the pre-aggregates and of the sets, and, when they all fit, the zone arrays of the leaves), so that they cost no pages of their own. The block is
  `{magic 0x3152524d, nranges, len, sum}`, `nranges` of `{stream offset, length, offset in the block}` and the bytes, at most `SEG_MIRROR_BYTES` (6144) of the page. It is a function of the stream bytes alone: the writer takes the
  ranges as it writes them, and `sift.col_verify` compares the sum and every range with the stream. A reader that does not know it never looks past the extents and reads the stream; a header page without the magic (a segment
  written before, a block that did not fit, a trailer a relocation moved) is read from the stream as before, and a rewrite or merge by a build that does not know it writes a segment without it. A reader refuses a block whose
  sum, length or ranges are damaged when the segment is opened or first read from it (corruption error), and a stream that differs from its mirror at `sift.col_verify`.
- The insert horizon of a connection (5.0.2) needs no column format minor and no flag, and takes no byte: the `reserved` word of the stamp a segment of a connected index stores for each connection (`SiftConnStamp`, 16 bytes, zero or `SIFT_CONN_STAMP_CLEAN` = 2 before) gets bit 0 (`SIFT_CONN_STAMP_HORIZON`) and, above bit 1, 30 bits that hold the parent index's insert horizon when the stamp was taken: the metapage word `inserted` (the records of the write buffers a promotion switched out, modulo 2^32, the word that was reserved and 0 in every earlier index) plus the records of the write buffers the parent holds, the count `SiftLanePageHead.nrecs` of their pages gives. A promotion adds the records of the buffer it replaces in the same switch of the directory that lists its segment; merges, rewrites and VACUUM leave the word alone, so the horizon only grows (modulo 2^32, compared modulo 2^30) and says how many rows came into the parent, whatever its segments were merged into: `sift.col_maintenance_status` of the child advises `REINDEX` when the rows that came since the stamp, less the entries that updates which kept their key wrote (the journal counts them), and the keys the journal says ended or changed, reach `sift.col_connect_refresh_pct` percent of the parent rows. A segment written before (bit 0 clear) says nothing of the rows that came since: the advice counts only the keys the journal records for it, and never a row it cannot count (a `REINDEX` of the child writes the horizon). A library that does not know it reads and writes the stamp as before (it tests only bit 1; its merges write stamps without the horizon, which the library of this release takes for stamps of unknown inserts), and leaves `inserted` as it is (a promotion by it adds nothing, so the horizon of the library of this release falls behind the rows that came in then: the advice of the child counts fewer rows until its segments are written again, never more). A rolled-back insert counts as one that came in.
- A group written by 3.0.1 under pressure with a tag but no version section is read as a constant version vector.

Zone flags: `SIFT_COLZ_NOSUM` 0x1, `SIFT_COLZ_NAN` 0x2,
`SIFT_COLZ_CONST` 0x4, `SIFT_COLZ_OVERFLOW` 0x8, `SIFT_COLZ_INLINE` 0x10, `SIFT_COLZ_JNULL` 0x20 (3.2, segment format 6: a NULL slot of the leaf is
