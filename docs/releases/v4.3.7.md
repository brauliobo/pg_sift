pg_sift 4.3.7: a patch release of 4.3.6 that adds `sift.col_repair`, which restores in place the liveness pages of a `sift_col` index that a `VACUUM` of 4.2.1 to 4.3.5 damaged in a segment of more than 65,151 superblocks, and teaches `sift.col_verify` to find that damage. It also closes two bounds: the slot counter of the small caches of the extension, and the number of groups a node of an aggregate can hold. Extension SQL 4.3.7 (one new function, no format change): install the files and restart the server, then `ALTER EXTENSION pg_sift UPDATE`.

## Highlights

- **Added: `sift.col_repair(index, dry_run)` restores, in place, the liveness pages that the dirty-bit bounds error damaged.** It takes the lock of `VACUUM` and the merges, restores the special space and the header of the pages, sets the dirty bit of each unit that has a cleared liveness bit and sets the count of dead rows to the number of cleared bits, one WAL record a page (a standby replays it; run it on the primary), and returns a row for each segment it changed (none when the index is sound; with `dry_run` it only reports). No format change.
- **Changed: `sift.col_verify` finds that damage.** It checks the liveness pages of every column segment: the type, flags, reserved field and generation of each page, that every unit with a cleared liveness bit has its dirty bit, and that the count of dead rows is the number of cleared bits. Each finding raises with the hint to run `sift.col_repair`. A read of a liveness page with flags or a reserved field set raises as it does for a wrong type or generation (the damage that was silent).
- **Fixed: the small caches of the extension no longer index before their array after 2^31 uses.** The BM25 estimate memo, the tests of a column scan, the order codes of a top-N and the refused lookups of the aggregate scan replaced their oldest entry in turn with a signed counter that was reduced by hand; past `INT_MAX` the counter was undefined behavior and then a negative remainder. They now take their slot from one helper with an unsigned count that is continuous across 2^32, and a lint rule refuses a counter that is incremented and reduced by hand.
- **Fixed: a node of an aggregate that holds more groups than a 32-bit count can name ends with an error.** The node that groups rows counted its groups in 32 bits, so a node holding 2^31 groups (reachable with a hash memory above about 30 GB) wrapped its capacity and wrote past its arrays. It now stops at the bound with an error that names the limit `rows_groups`.

## Who is affected and what to do

- **Affected by the bounds error that `sift.col_repair` repairs:** an index with a column segment of more than 65,151 superblocks (a very large segment) in which a `VACUUM` or a delete marked rows dead, on 4.2.1 to 4.3.5. 4.3.6 no longer damages the pages.
- **Update (the steps, in this order):** install the files and restart the server (a standby too), then `ALTER EXTENSION pg_sift UPDATE` in each database.
- **What to do after the update:** `SELECT * FROM sift.col_repair('<index>', true)` lists the damaged segments of a `sift_col` index (none: it is sound) and `SELECT * FROM sift.col_repair('<index>')` restores them; `REINDEX` remains the way when it says a page cannot be restored. `sift.col_verify('<index>')` finds the same damage.
- **Going back:** install the 4.3.6 files and restart after `ALTER EXTENSION pg_sift UPDATE TO '4.3.6'`; `sift.col_repair` stays in the catalog and fails to find its function in that library.

## Compatibility

- PostgreSQL 17, 18 and 19; the packages below cover all three (other builds from source with `make USE_PGXS=1`). A replacement of 4.3.6 with the install; extension SQL 4.3.7 (`pg_sift--4.3.6--4.3.7.sql`, one function); no column format minor and no BM25 metapage minor changes.

## SQLite extension

pg_sift for SQLite 4.3.7 (`sift`, a loadable extension; a separate component from the PostgreSQL extension above). Rebuilt with the PostgreSQL 4.3.7 release: no change to the SQL interface or the shared format.

- **No change:** the changes of this release are in the PostgreSQL column index, which is not in this extension. No speed-up or slow-down is claimed.
- Needs SQLite 3.38 or newer; Linux x86-64, glibc 2.34 or newer. Built on Debian 12, loaded into the SQLite of Debian 12, Ubuntu 24.04 and AlmaLinux 10 before release.
- Storage format 2: tables of 3.4.0 to 3.7.0 open as they are, nothing to rebuild.

Download `sift-sqlite-4.3.7-linux-x86_64.tar.gz` (below, covered by `SHA256SUMS` with the packages), unpack it and `.load ./sift` from the `sqlite3`
shell (`sha256sum --ignore-missing -c SHA256SUMS`). Documentation: [sqlite/README.md](https://github.com/brauliobo/pg_sift/blob/v4.3.7/sqlite/README.md).
Every change: [sqlite/CHANGELOG.md](https://github.com/brauliobo/pg_sift/blob/v4.3.7/sqlite/CHANGELOG.md).

## MariaDB extension

pg_sift for MariaDB 4.3.7 (`sift`, a UDF library and two SQL files; a separate component from the extensions above). Rebuilt with the PostgreSQL 4.3.7 release: no change to the SQL files.

- **No change:** the changes of this release are in the PostgreSQL column index, which is not in this extension. No speed-up or slow-down is claimed.
- One library per MariaDB series, because it calls the server's own symbols and refuses to load into another series: 10.11, 11.4, 11.8, 12.1 and 13.0; Linux x86-64. Each was built in the stock `mariadb:<series>` image against that server's headers and loaded into a server of the same image before release. `BUILD-INFO` in the tarball lists the server version and the glibc each library needs.
- Index format 2: an index of 3.4.0 to 3.7.0 opens as it is, nothing to rebuild.

Download `sift-mariadb-4.3.7-linux-x86_64.tar.gz` (below, covered by `SHA256SUMS` with the packages), unpack it, copy `lib/<series>/libsift_udf.so` of your server's series
(`SELECT VERSION()`) into its `plugin_dir`, then `SOURCE sql/functions.sql` once per server and `sql/sift.sql` once per database (`sha256sum --ignore-missing -c SHA256SUMS`).
Documentation: [mariadb/README.md](https://github.com/brauliobo/pg_sift/blob/v4.3.7/mariadb/README.md).
Every change: [mariadb/CHANGELOG.md](https://github.com/brauliobo/pg_sift/blob/v4.3.7/mariadb/CHANGELOG.md).
