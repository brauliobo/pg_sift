pg_sift 3.2.2: a fix for the plan estimates of partitions and inheritance children of a table under row-level security, and for roles that the aggregate pushdown refused. A drop-in replacement of 3.2.1: install the new files and restart the server.

## Highlights

- **Fixed: the row estimate of a `@@>` condition on a partition or an inheritance child of a table under row-level security.** The estimate came from the statistics of the whole `sift` index, which include the rows a policy hides, so the rows shown by `EXPLAIN` for a role under the policy depended on them. The documentation already said that a role under a policy gets no index estimate (3.2.0 and 3.2.1 did that for a table without partitions, but not for the partitions and children of one, which carry the parent's policy in their restrictions). The estimate is the planner's default now, as for a table without partitions. The query results were not affected: the rows a policy hides were never returned. The refusal of `sift.score()` on such a table names the table under the policy (it said that a sift index is needed on every partition).
- **Fixed: `permission denied for table` from an aggregate that the normal plan answers.** A role with `SELECT` on some columns of a table, or on a view and not on its table, got the error at run time when the plan was `Custom Scan (SiftAgg)`, while `sift.enable_agg = off` answered. The scan checked table-level `SELECT` of the invoking role; it now leaves the privileges to PostgreSQL, which checks the columns, and the view owner's rights, before the scan starts. Row-level security is still refused by the scan, and a view over a table with it keeps the normal plan.

## Who is affected and what to do

- **Partitions and inheritance children under a policy:** servers that have a table with `ENABLE ROW LEVEL SECURITY` that is partitioned (or has inheritance children) with a `sift` index on its partitions or children, and roles that read it through the parent without being its owner or having `BYPASSRLS`. Other tables, and servers without row-level security, are not affected. Installing the new library fixes it; no `REINDEX`, no change of the extension SQL.
- **Roles with column privileges or a view:** a role that read an aggregate through column privileges or a view got the error above (the table-level check was in 3.2.0 and 3.2.1); a workaround until the update is `SET sift.enable_agg = off` for that role (`ALTER ROLE ... SET sift.enable_agg = off`).

## Compatibility

- PostgreSQL 17 and 18; PostgreSQL 19 is experimental. A drop-in replacement of 3.2.1: extension SQL 3.2, no change of the BM25, `sift_col` or `sift_table` formats. Install the new files (a library swap) and restart the server; going back to 3.2.1 needs nothing.

## Packages

x86-64 packages for PostgreSQL 18 are attached below (`SHA256SUMS` covers every asset); other versions build from source with `make USE_PGXS=1`. The packages depend on `liblz4` and `libzstd`.

- Debian 13, Ubuntu 24.04 (PGDG `postgresql-18`): `sudo apt install ./postgresql-18-pg-sift_3.2.2-1_amd64.deb`
- RHEL, Rocky, Alma 9 and 10 (PGDG `postgresql18-server`): `sudo dnf install ./pg_sift_18-3.2.2-1.el9.x86_64.rpm`
- Arch Linux: AUR `pg_sift`.

## SQLite extension

pg_sift for SQLite 3.2.2 (`sift`, a loadable extension; a separate component from the PostgreSQL extension above). Rebuilt with the PostgreSQL 3.2.2 release: no change to the storage format, the SQL interface or the shared core.

- **No change:** the fix of this release is in the PostgreSQL planner, which is not in this extension. No speed-up or slow-down is claimed.
- Needs SQLite 3.38 or newer; Linux x86-64, glibc 2.34 or newer. Built on Debian 12, loaded into the SQLite of Debian 12, Ubuntu 24.04 and AlmaLinux 10 before release.
- Storage format 2: tables of 3.2.1 open as they are, nothing to rebuild.

Download `sift-sqlite-3.2.2-linux-x86_64.tar.gz` (below, covered by `SHA256SUMS` with the packages), unpack it and `.load ./sift` from the `sqlite3`
shell (`sha256sum --ignore-missing -c SHA256SUMS`). Documentation: [sqlite/README.md](https://github.com/brauliobo/pg_sift/blob/v3.2.2/sqlite/README.md).
Every change: [sqlite/CHANGELOG.md](https://github.com/brauliobo/pg_sift/blob/v3.2.2/sqlite/CHANGELOG.md).

## MariaDB extension

pg_sift for MariaDB 3.2.2 (`sift`, a UDF library and two SQL files; a separate component from the extensions above). Rebuilt with the PostgreSQL 3.2.2 release: no change to the index format, the SQL files or the shared core.

- **No change:** the fix of this release is in the PostgreSQL planner, which is not in this extension. No speed-up or slow-down is claimed.
- One library per MariaDB series, because it calls the server's own symbols and refuses to load into another series: 10.11, 11.4, 11.8, 12.1 and 13.0; Linux x86-64. Each was built in the stock `mariadb:<series>` image against that server's headers and loaded into a server of the same image before release. `BUILD-INFO` in the tarball lists the server version and the glibc each library needs.
- Index format 2: an index of 3.2.1 opens as it is, nothing to rebuild.

Download `sift-mariadb-3.2.2-linux-x86_64.tar.gz` (below, covered by `SHA256SUMS` with the packages), unpack it, copy `lib/<series>/libsift_udf.so` of your server's series
(`SELECT VERSION()`) into its `plugin_dir`, then `SOURCE sql/functions.sql` once per server and `sql/sift.sql` once per database (`sha256sum --ignore-missing -c SHA256SUMS`).
Documentation: [mariadb/README.md](https://github.com/brauliobo/pg_sift/blob/v3.2.2/mariadb/README.md).
Every change: [mariadb/CHANGELOG.md](https://github.com/brauliobo/pg_sift/blob/v3.2.2/mariadb/CHANGELOG.md).
